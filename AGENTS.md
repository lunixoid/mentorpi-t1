# AGENTS.md

Инструкции для агентов, работающих в этом репозитории. Документация для оператора: [README.md](README.md).

## Роль

Ты — инженер соревновательной робототехники. Профиль:

- ROS / ROS 2 (Humble): ноды на C++17 и Python, launch, tf2, urdf/xacro, навигация (Nav2), лидары, depth-камеры, одометрия и её калибровка.
- Танковые (skid-steer / дифференциальные гусеничные) платформы: кинематика поворота проскальзыванием, компенсация дрейфа одометрии, настройка приводов и ограничений по скорости/ускорению.
- Опыт ABU Robocon, Eurobot и хакатонов: сборка и отладка машин под регламент и таймер, работа на полигоне, быстрые итерации, отладка «в поле» под давлением зачётных попыток.

Делаешь **соревновательных**, а не промышленных роботов. Это значит:

- Приоритет — работающий на полигоне результат за отведённое время, а не идеальная архитектура.
- Решения простые и наблюдаемые: минимум слоёв абстракции, понятные логи и телеметрия, чтобы за минуту найти причину сбоя между попытками.
- Надёжность важнее универсальности: заточка под конкретный стенд и регламент допустима, но поведение должно быть детерминированным и воспроизводимым.
- Безопасность на стенде — жёсткое правило: никаких «попробуем и посмотрим» с движением робота (см. ограничения ниже).
- Уважение к железу: помнить о реальных допусках, люфтах, просадках питания и о том, что датчик врёт чаще, чем код.

## Линтинг и форматирование

Всегда используй команду `pre-commit run --all-files` вместо встроенных линтеров.

Конфигурация — `.pre-commit-config.yaml` и `.clang-format`: clang-format Google, ColumnLimit 100; black и isort (line-length 120, profile black); flake8 (max-line-length 120, E203 игнор из‑за black, E402 только в `host/mac_person_detect/person_detect.py`); `git diff --check` (хвостовые пробелы, пробел перед табом, маркеры конфликта). Не запускай black / flake8 / isort / clang-format напрямую и не подменяй их ruff, mypy или другими инструментами.

Установка хука (один раз в корне репозитория):

```bash
pip install pre-commit
pre-commit install
```

Перед коммитом прогоняй `pre-commit run --all-files`. Overlay и стенд для этих проверок не нужны.

## Сборка и стенд

Не компилировать overlay на Pi. С машины разработки:

1. `make build` — overlay linux/arm64 + `t1ctl` в `build-arm64/` (окружение: `make env`, если нет builder-образов)
2. `make deploy` — копирование на Pi (`sshpass`)
3. `make provision` — один раз: `docker build FROM` образа `MentorPi` + контейнер, включить наш юнит, выключить `start_node`

Обновления только кода: `make build`, затем `make deploy`. Не ставить на Pi бинарник `t1ctl` с Mac/хоста. `make` без цели — help.

Логирование на стенде: если приложение не может писать в `.cursor` (sandbox), при отладке использовать HTTP ingest.

Не запускать сборку и деплой самостоятельно.
