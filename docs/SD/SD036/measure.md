# Замер объезда по виртуальному бамперу (SD036)

Операторский документ T7 [SD036](tech.md). Заполняется на стенде; агент числа не подставляет. Проверки T5 и T6 на живом графе собраны сюда же, чтобы пройти стенд один раз.

Что снимается: габарит робота, поведение в сценариях BA ([solution.md](solution.md)), бэги для разбора и итоговые параметры бампера. Приёмка качественная, как в SD025: вердикт оператора по проездам.

## Безопасность

- Робота в движение приводит **только оператор**. Агент не публикует Twist, не делает `ros2 topic pub` в `/cmd_vel`, `/vehicle/cmd_vel`, `/hiwonder_controller/cmd_vel`.
- Оператор **у пульта** весь протокол. Мгновенный стоп: кнопка **Select** (режим Manual) или на хосте Pi `t1ctl mode forbid`.
- Охрана работает только в AutoFollow. В Manual пульт ведёт робота **без охраны**.
- Охрана **не защищает от наезда на людей**: люди не препятствия по решению оператора. Помощник, который изображает чужого человека, стоит неподвижно и отходит сам.
- Лидар видит одну плоскость на высоте 0.18 м. Предметы для сценариев — **выше 0.18 м** (стул, коробка выше колена, щит). Низкие предметы, стекло и ступени не видны.
- Пропажа лидара — робот **едет без охраны**. Сценарий 8 — только в свободном секторе.
- Проверки с человеком в кадре в AutoFollow двигают робота. На статических проверках (раздел «Граф») робот стоит на подставке с гусеницами в воздухе или оператор держит Select под пальцем.

## Подготовка

На машине разработки: `make build`, `make deploy`. На Pi:

```bash
t1ctl start
t1ctl mode forbid
t1ctl status
```

Ожидается: `demo active`, `chassis active`, `mode forbidden`, `lidar active`, `camera active`. Если контур или сенсоры не `active` — дальше не идти.

Команды ROS ниже выполняются в контейнере:

```bash
docker exec -it -u ubuntu mentorpi-t1 bash -lc '
  source /home/ubuntu/ros2_ws/.hiwonderrc; export ROS_LOCALHOST_ONLY=0;
  source /home/ubuntu/mentorpi_t1_ws/install/setup.bash; bash'
```

Строки старта нод печатают все параметры:

```bash
docker logs mentorpi-t1 2>&1 | grep -E "motion_control started|avoidance (on|off)|obstacle_guard started" | tail -3
```

**Ловушка:** параметры читаются только на старте. `ros2 param set` на живой ноде поведение не меняет. Кандидат параметров — правка YAML в `install/motion_control/share/motion_control/config/` на Pi и `t1ctl restart`, либо ручной запуск ноды, как в SD025.

## Габарит (D3.1)

Стартовые значения — огибающая мешей URDF, не замер. Начало `base_footprint` — центр разворота на месте (середина гусениц по длине и ширине).

| Величина | As-built (меш) | Рулетка | В `footprint.yaml` |
|----------|----------------|---------|--------------------|
| `footprint_front` — от центра до передней кромки, м | 0.175 | | |
| `footprint_back` — от центра до задней кромки, м | 0.166 | | |
| `footprint_half_width` — половина ширины по гусеницам, м | 0.123 | | |

Расхождение больше 1 см — вписать в `footprint.yaml` (общий для обеих нод).

## Запись бэга

Один бэг на сценарий, имя `sd036_<сценарий>_<ГГГГММДД_ччммсс>`:

```bash
ros2 bag record -o sd036_<scenario>_$(date +%Y%m%d_%H%M%S) \
  /scan /perception/persons /perception/nearest_person /pnc/desired_twist \
  /pnc/obstacle_avoidance/status /control/motion_restriction /control/state \
  /vehicle/cmd_vel /odom_raw /tf /tf_static
```

## Сценарии (BA)

Режим AutoFollow (`t1ctl mode allow`), оператор-цель в кадре, пульт у второго человека или у оператора. Каждый сценарий — 2–3 проезда. «Касание» — любой контакт корпуса или гусениц с предметом.

| # | Сценарий | Расстановка | Ожидание | Бэг | Касание | Вердикт |
|---|----------|-------------|----------|-----|---------|---------|
| S1 | Стул на пути | стул сбоку от прямой робот—человек (смещение 0.2–0.3 м), человек в 2.5–3 м | робот обтекает стул дугой, статус AVOIDING → FREE, доезжает до дистанции удержания; `obstacle` в охране нет | | | |
| S2 | Дверной проём | проём ~0.6 м, человек за ним | робот замедляется и проходит проём; при узком проёме — BLOCKED перед ним без касания | | | |
| S3 | Предмет вплотную | коробка шириной ~0.3–0.5 м в 0.1 м перед роботом, человек по диагонали за ней | ROTATE, затем ARC, касаний нет. По симуляции нужный разворот шире полуугла камеры: человек уходит из кадра, робот встаёт (D4.6). Записать, так ли на стенде | | | |
| S4 | Тупик | робот заехал в карман из коробок, впереди стенка | REVERSE, затем попытка объезда; касаний нет | | | |
| S5 | Окружён | коробки со всех сторон в ~3 см | BLOCKED, команда ноль, робот стоит | | | |
| S6 | Чужой человек на пути | помощник стоит неподвижно между роботом и оператором | робот **не объезжает** человека (FREE, `excluded_points > 0`); оператор останавливает пультом до контакта | | | |
| S7 | Нет человека, впереди предмет | оператор уходит из кадра | робот стоит, `reason: no_target`, никаких манёвров | | | |
| S8 | Пропажа лидара | свободный сектор, `pkill -f ldlidar_stl_ros2_node` во время следования | статус NO_SCAN, следование без охраны; вернуть `t1ctl restart` | | | |
| S9 | Предмет на линии к человеку (ограничение D4.6, принято оператором) | стул ровно на прямой робот—человек, в 0.6–1 м перед роботом | касаний нет; объезд требует доворота больше полуугла камеры, человек выходит из кадра, робот встаёт. Человек делает шаг в сторону и возвращается в кадр — следование продолжается | | | |

## Итоговые параметры

Заполняется после разбора бэгов. Стартовые — I4.2, I4.3, I5.

| Параметр | Стартовое | Итог | Почему |
|----------|-----------|------|--------|
| `margin_min` | 0.05 | | |
| `margin_max` | 0.20 | 0.12 | бэг `sd036_bed_20260918_151838`: на 0.25 м/с робот держал 0.22–0.25 м от кровати (0.20 + гистерезис 0.03) и не доворачивал к человеку; в симуляции при 0.12 проём 9.9 с вместо 12.6, слалом 12.2 с вместо 16.6, касаний и `obstacle` нет |
| `horizon_s` | 1.5 | | |
| `kp_repulse` | 0.01 | | |
| `influence_range` | 0.40 | 0.25 | тот же бэг: отталкивание в 0.25–0.40 м выбирало медленные дуги вдоль кровати |
| `person_exclusion_radius` | 0.35 | 0.25 | бэг `sd036_bed_20260918_133606`: при 0.35 край кровати у человека выпадал из препятствий (планировщик видел 0.77 м вместо 0.11); при 0.25 кровать видна, ноги идущего человека (до 0.22 м от центра) ещё исключены |

## Вердикт оператора

Дата: 2026-09-18. Решение оператора: закрыть SD036 («давай закрывать sd036»). Комментарий: объезд вдоль кровати работает без касаний после подбора `person_exclusion_radius`, `margin_max`, `influence_range`; сценарии S2–S9 целиком не проезжены, габарит не сверен. Проезд с коробкой 55 см показал, что цель ложится на препятствие в рамке детекции (восприятие F08) — вынесено в новый SD вместе с памятью цели.
