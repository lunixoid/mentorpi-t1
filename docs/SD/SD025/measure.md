# Замер сведённого закона следования (SD025)

Операторский документ T5 [SD025](tech.md). Заполняется на стенде; агент числа не подставляет.

Снимаются четыре величины: `max_linear_follow`, `kp_lin`, `accel_linear`, `decel_linear`.
Плюс описываются словами оператора два известных свойства закона — ступенька на границе
коридора (`tech.md` D3.1) и фактическое место остановки (D3.3).

## Безопасность

Охраны столкновений (**F12**, **F13**) **нет** — робот не тормозит перед предметами и видит
только человека-цель. Все прогоны — на ровном полу, в свободном секторе впереди. В SD025
робот **едет и доворачивает одновременно**, поэтому свободным должен быть и сектор по
сторонам, а не только прямо по курсу.

Оператор **у пульта** на всём протоколе. Мгновенный стоп:

- кнопка **Select** на пульте → режим **Manual**, канал следования отключается;
- на хосте Pi под рукой: `t1ctl mode forbid`.

Робота в движение приводит **только оператор**. Запрещены ненулевые Twist от агента,
`ros2 topic pub` в `/cmd_vel`, `/vehicle/cmd_vel`, `/hiwonder_controller/cmd_vel` и любые
иные команды движения не от оператора.

## Ловушка: параметры читаются только на старте

`motion_control` разбирает параметры в конструкторе ноды и не подписан на их изменение.
**`ros2 param set` на живой ноде закон не меняет** — `param get` покажет новое число, а
команда останется считаться по старому. Каждый кандидат — это перезапуск ноды.

Порядок смены кандидата (на хосте Pi):

```bash
t1ctl mode forbid
```

```bash
docker exec -it -u ubuntu mentorpi-t1 bash -lc '
  source /home/ubuntu/ros2_ws/.hiwonderrc; export ROS_LOCALHOST_ONLY=0;
  source /home/ubuntu/mentorpi_t1_ws/install/setup.bash;
  pkill -f "motion_control/motion_control";
  sleep 1;
  ros2 run motion_control motion_control --ros-args \
    -p standoff:=0.5 -p max_linear:=0.37 -p max_angular:=2.0 \
    -p kp_lin:=0.8 -p kp_ang:=1.5 \
    -p dist_deadband:=0.05 -p min_breakaway_linear:=0.10 \
    -p accel_linear:=0.30 -p decel_linear:=0.60 \
    -p max_linear_follow:=0.20 \
    -p ang_deadband:=0.05 -p track_half_sum:=0.1407 \
    -p nearest_timeout_ms:=300 -p rate_hz:=20.0'
```

Менять в этой команде только подбираемый параметр, остальные держать как в launch — иначе
непонятно, что именно дало эффект. `.hiwonderrc` включает `ROS_LOCALHOST_ONLY=1`; без
`export ROS_LOCALHOST_ONLY=0` нода не увидит топики, хотя запустится.

По завершении замера — вернуть штатный запуск (`t1ctl restart` или перезапуск контура), чтобы
нода снова поднималась из launch, а не из ручной команды.

## Прогон 1 — потолок скорости следования (`max_linear_follow`)

**Постановка.** Режим **AutoFollow**. Человек-цель отходит от робота далеко вперёд (метра на
два-три), чтобы подъезд успел выйти на насыщение. Оператор оценивает, какая максимальная
скорость подъезда **безопасна** на этой площадке: зазор до стен и мебели, комфорт торможения,
отсутствие F12/F13. На входе в SD025 стоит `0.20` м/с, и это то самое «медленно», ради
которого заведён замер. Потолок не может превышать путевой `max_linear = 0.37` м/с.

Подбор идёт **первым**, потому что от потолка зависят и форма профиля (прогон 2), и ощущение
темпов (прогон 3): бюджет доворота D2.2 тоже считается от него.

## Прогон 2 — крутизна профиля (`kp_lin`), ступенька D3.1 и недоезд D3.3

**Постановка.** Режим **AutoFollow**, потолок — снятый в прогоне 1. `kp_lin` задаёт три вещи
сразу, и смотреть надо все три:

1. **С какой дистанции робот едет на потолке.** Насыщение наступает при
   `err ≥ max_linear_follow / kp_lin`. При `kp_lin = 0.8` и потолке `0.20` это `err = 0.25` м,
   то есть с дистанции ≈`0.75` м. Больше `kp_lin` — раньше выходит на полную.
2. **Ступенька на границе коридора (D3.1).** Сразу за коридором закон выдаёт
   `kp_lin · dist_deadband`, а не ноль: при `0.8 × 0.05` это `0.04` м/с. Подъём `kp_lin`
   ступеньку **увеличивает** — при `1.5` будет `0.075` м/с.
3. **Недоезд до коридора (D3.3).** Если `kp_lin · err` падает ниже физического порога
   страгивания раньше, чем робот дойдёт до коридора, он встанет **чуть дальше** нужного.
   Смещение ≈ `порог / kp_lin`, то есть больше `kp_lin` — меньше недоезд.

Пункты 2 и 3 тянут в разные стороны, и выбор — операторский компромисс.

Оператор отходит дальше коридора, даёт роботу подъехать до полной остановки, **рулеткой**
меряет фактическую дистанцию от носа робота до себя и сравнивает с `standoff = 0.5` м.
Повторить на нескольких `kp_lin`.

**Что снимать.**

```bash

```

```bash

```

Смотреть: `person.x`, `person.y`, `valid`, `coasting`, `range ≈ hypot(x, y)` в момент
остановки; значение `linear.x` в последний тик перед нулём — это и есть наблюдаемая ступенька.

## Прогон 3 — темпы разгона и торможения (`accel_linear`, `decel_linear`)

**Постановка.** Режим **AutoFollow**, потолок и `kp_lin` — снятые в прогонах 1–2. Стартовые
`0.30` и `0.60` м/с² — не замер, а разумная точка старта: разгон до `0.20` м/с занимает
примерно `0.7` с, торможение вдвое резче.

Смотреть три вещи:

1. **Старт.** Трогание не должно быть рывком по гусеницам, но и не должно ощущаться как
   задержка реакции на ушедшего человека. Слишком малый `accel_linear` — робот «думает».
2. **Проскок коридора.** Слишком малый `decel_linear` — робот проезжает коридор и потом стоит
   ближе `standoff`. Проверяется рулеткой, как в прогоне 2.
3. **Реакция на пропажу цели.** Стоп по гейту рампу **не проходит** (D4): при закрытии
   человека рукой `desired_twist` обязан стать нулевым в пределах одного тика (`0.05` с при
   `rate_hz = 20`), без плавного спада. Если виден спад — это дефект, а не настройка.

**Что снимать.**

```bash
ros2 topic echo /pnc/desired_twist --field linear.x
```

```bash

```

## Прогон 4 — связка каналов на итоговых числах

**Постановка.** Режим **AutoFollow**, все четыре параметра — итоговые. Это не подбор, а
проверка, что сведённый закон ведёт себя целиком: доворот не душит скорость и скорость не
душит доворот (бюджет D2.2 считается от `max_linear_follow`, который поменялся в прогоне 1).

Оператор идёт **по дуге** дальше коридора, оставаясь в кадре, и смотрит, держится ли он по
курсу. Затем — резкое смещение вбок на ходу: доворот должен появиться на разгоне, а не
пропасть.

**Что снимать.**

```bash
ros2 topic echo /pnc/desired_twist
```

Смотреть одновременно `linear.x` и `angular.z`. Ожидается: оба ненулевые в движении по дуге;
`angular.z` ненулевой **в том числе** когда `linear.x` на потолке; оба ровно нулевые, когда
человек в коридоре и просто смещается вбок (доворота на месте нет).
