# SD030. Технический дизайн

BA: [solution.md](solution.md). Дизайн UI: skipped (экранов и команд не добавляем). Каталог: F08. СА без Plan-гейта — оператор делегировал: «требования пишешь ты, код пишут cursor-agent composer-2.5».

As-is (бэг `f11_sd028_offline_20260912_095744`, 182 с, разбор `scratch/sd028/a12.py`, `a15.py`). `person_detect_pi` гоняет NCNN раз в `infer_period_ms=500`, между инференсами перепубликует последнюю рамку со штампом текущего кадра RGB. `person_perception` берёт свежее облако (после SD029 10 Гц, выпадений 0 %) и ищет ближайший кластер **внутри рамки**. Рамка старше момента облака в среднем на 0.35 с (p90 0.55, max 0.55): 0.25–0.5 с ожидания следующего инференса плюс ~0.24 с самого инференса. На довороте робот за это время поворачивается на 7° (p90 14.3, max 24.6), и кластер в старой рамке даёт старое направление. Отклик пеленга на собственный поворот — 0.17 вместо 1.0; 14 доворотов из 31 закончились за целью; 24 остановки из 27 — коуст после ухода человека из рамки.

## Системный дизайн

1. **D1.** Восприятие поворачивает рамку детекции на собственный поворот робота, прежде чем искать в ней глубину.
   1. **D1.1.** Время рамки — штамп кадра, по которому она посчитана. `person_detect_pi` кладёт его в `header.stamp` **каждой** `Detection2D`; заголовок массива остаётся штампом текущего кадра RGB, как сейчас (на нём держатся окна свежести SD027 и предупреждение о задержке SD014). Mac уже ставит в `Detection2D.header` штамп своего кадра. Штамп нулевой — берётся заголовок массива.
   2. **D1.2.** Угол поворота `Δψ` = yaw(`odom` → `base_footprint`, штамп облака) − yaw(тот же TF, штамп рамки). TF `odom` → `base_footprint` публикует вендорный `odom_publisher` (см. `stage1.launch.py`), буфер TF в ноде уже есть. Новых подписок и зависимостей нет.
   3. **D1.3.** Сдвиг рамки — поворот луча в оптической плоскости: для каждой вертикальной границы `u` рамки `u' = cx + fx · tan(atan((u − cx) / fx) + Δψ)`. По вертикали рамка не двигается. Формула точна для чистого поворота; смещение робота вперёд за 0.35 с (≈9 см при 0.25 м/с) не компенсируется — на пеленг оно влияет много слабее.
   4. **D1.4.** Границы применимости: поправка считается, только если интринсики есть, TF на обе метки времени доступен, модуль возраста рамки `|t_cloud − t_рамки| ≤ ego_max_age_s` (в Mac-режиме облако бывает снято раньше кадра; знак `Δψ` сам разворачивает поправку) и `|Δψ| ≤ ego_max_yaw_rad`. Иначе рамка идёт как есть — поведение до SD030. Отказ TF логируется троттлингом, наблюдение не выбрасывается.
   5. **D1.5.** После сдвига рамка обрезается по кадру. Если от неё не осталось пересечения с кадром, наблюдение не публикуется: человек вышел из поля зрения, дальше действуют правила SD017/SD028 (удержание, затем пустой nearest).
   6. **D1.6.** Выключатель `ego_compensation_enabled` (по умолчанию `true`). Значение `false` возвращает поведение до SD030.
2. **D2.** `infer_period_ms` остаётся 500 мс. Учащение до 250 мс замерено на стенде и откачено: нода не успевает перепубликовывать рамки между инференсами (3.2 Гц вместо 10), ядра 85–92 %, кадры камеры 8.7 Гц, а возраст рамки вырос с 0.35 до 0.58–0.80 с — под нагрузкой инференс считается дольше и берёт устаревший кадр из очереди. 400 мс: 10.9 Гц рамок, ядра 71–76 %, кадры 9.4 Гц, выигрыша по возрасту рамки нет. Значит, на этом железе более свежую рамку учащением не получить; вклад поворота робота убирает D1, и этого достаточно для доворота. Свежесть рамки вернётся к разговору, только если появится способ считать инференс дешевле.
3. **D3.** Не меняется (ограничение scope, задач нет): закон следования и `motion_control`; захват цели SD017/SD028 и его пороги; окна свежести SD027; трекер ByteTrack; транспорт и профиль Fast DDS SD029; вендорный драйвер камеры; `t1ctl`, `mk/*`, launch; `mentorpi_msgs`; Mac-скрипты.
4. **D4.** Версии: `mentorpi_person_detect` 0.2.0 → 0.3.0 (штамп кадра инференса в каждой рамке), `mentorpi_perception` 0.7.0 → 0.8.0 (поправка на поворот).
5. **D5.** Приёмка на стенде после `make build` / `make deploy`: неходовая часть — агент (параметры, стартовые строки, частоты кадров, загрузка ядер), ходовая — оператор (довороты). По бэгу сравниваются доля доворотов с перекрутом и отклик пеленга на поворот (`scratch/sd028/a12.py`). Каталог SD001: у F08 появляется ссылка на SD030.

```mermaid
sequenceDiagram
  participant Aurora as aurora930_node
  participant Detect as person_detect_pi
  participant Perc as person_perception
  participant TF as tf odom->base_footprint
  participant MC as motion_control

  Aurora->>Detect: rgb frame (stamp t_frame)
  Note over Detect: NCNN every 500 ms; between runs the last boxes are republished
  Detect->>Perc: detections_2d_onboard (array stamp = now, each box stamp = t_frame)
  Aurora->>Perc: points2 (stamp t_cloud)
  Perc->>TF: yaw at t_frame, yaw at t_cloud
  TF-->>Perc: dpsi
  Perc->>Perc: rotate bbox by dpsi, then nearest cluster inside it
  alt box still inside the frame
    Perc->>MC: nearest with the bearing the robot sees now
  else box rotated out of the frame
    Perc->>MC: no observation (SD017/SD028 rules)
  end
```

## Программные интерфейсы

### Функции модуля C++

1. **I1.** `person_geometry.hpp`
   1. **I1.1.** `inline BboxPx rotate_bbox_yaw(const BboxPx& box, const CameraIntrinsics& cam, double dyaw_rad);` — сдвиг границ по D1.3. При `dyaw_rad == 0` рамка возвращается без изменений.
   2. **I1.2.** `inline bool bbox_clip_to_image(const BboxPx& box, const CameraIntrinsics& cam, BboxPx* out);` — обрезка по кадру; `false`, если пересечения с кадром нет.

### ROS: топики и параметры

2. **I2.** `/perception/detections_2d_onboard` (`vision_msgs/Detection2DArray`): `header.stamp` — текущий кадр RGB, как сейчас; **новое**: `detections[i].header.stamp` — штамп кадра, по которому посчитана рамка. Поле `detections[i].id` и `bbox` без изменений.
3. **I3.** [person_perception.yaml](../../src/mentorpi_perception/config/person_perception.yaml): `ego_compensation_enabled: true`, `ego_max_age_s: 1.0`, `ego_max_yaw_rad: 0.6`, `odom_frame: odom`. Комментарий — SD030, откуда числа (возраст рамки p90 0.55 с, поворот max 25°), не SLA.
4. **I4.** [person_detect_pi.yaml](../../src/mentorpi_person_detect/config/person_detect_pi.yaml): `infer_period_ms` остаётся 500 с комментарием SD030 о замеренном и откаченном учащении (D2).

### Логи

5. **I5.** `person_perception`, троттлинг 5 с: `ego yaw compensation dpsi=%.1f deg shift=%.0f px age=%.2f s` при применённой поправке; `ego compensation skipped: %s` (нет TF / возраст вне окна / поворот больше предела).

## Изменения в приложениях

### `mentorpi_person_detect/person_detect_pi`
**Пункты:** D1.1, D2, D4 (detect), I2, I4

Нода публикует рамки как на свежем инференсе, так и перепубликацией между инференсами. Сейчас она переписывает штамп каждой рамки на текущий кадр, из-за чего потребитель не может узнать возраст рамки. Меняется только это и частота инференса.

1. Запомнить штамп кадра, по которому посчитан последний инференс, и ставить его в `header.stamp` каждой `Detection2D` — и при свежей публикации, и при перепубликации.
2. Заголовок массива по-прежнему переписывается на текущий кадр RGB (`publish_last`), окна SD027 не трогаем.
3. `infer_period_ms: 500` в YAML с комментарием SD030 (учащение замерено и откачено, D2). `package.xml` 0.3.0.
4. Не трогаем: трекер и его параметры, модель, QoS, топики, поведение `enabled`.

### `mentorpi_perception/person_geometry`
**Пункты:** D1.3, D1.5, I1

Header-only геометрия: перевод рамки в пиксели, поиск ближайшего кластера, перевод в базу. Добавляются две чистые функции — поворот рамки и обрезка по кадру, обе с тестами.

1. `rotate_bbox_yaw` по формуле D1.3 (I1.1).
2. `bbox_clip_to_image` (I1.2).
3. Не трогаем: `nearest_cluster_in_bbox`, `bbox_from_detection`, пороги `kClusterSlabM` / `kClusterMinPoints`.

### `mentorpi_perception/person_perception`
**Пункты:** D1.2, D1.4, D1.6, D4 (perception), I3, I5

Нода считает наблюдения по рамке и облаку. Добавляется шаг между разбором рамки и поиском кластера: рамка поворачивается на собственный поворот робота, взятый из TF по двум меткам времени.

1. Параметры I3, проверка диапазонов на старте, значения в стартовую строку.
2. Для каждой рамки: время рамки (`Detection2D.header.stamp`, ноль → заголовок массива), время облака (`header.stamp` облака), `Δψ` через `tf_buffer_->lookupTransform(odom_frame, base_frame, stamp)` на обе метки, проверки D1.4, затем `rotate_bbox_yaw` и `bbox_clip_to_image`; нет пересечения с кадром — наблюдение не добавляется.
3. Логи I5.
4. `package.xml` 0.8.0.
5. Не трогаем: захват цели и его параметры, окна свежести, выбор источника рамок, overlay, ping DDS, публикуемые контракты.
