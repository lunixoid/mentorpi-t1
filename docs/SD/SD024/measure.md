# Замер линейного канала следования (SD024)

Операторский документ T5 [SD024](tech.md).

## Решение оператора (2026-09-06)

Четыре инструментальных прогона **не проводились**. Свип стика с IMU как свидетелем «поехал»
не годится: на стоящем роботе IMU продолжает давать «едет» (шум/дрейф, не старт гусениц).

Следование за человеком на стартовых I3 уже работает. Меняем только потолок канала:

| Параметр | Было (I3) | Стало | Почему |
|----------|-----------|-------|--------|
| `max_linear_follow` | `0.15` м/с | **`0.20` м/с** | оператор: чуть быстрее; путевой `max_linear = 0.37` не трогаем |
| `min_breakaway_linear` | `0.10` | `0.10` | без изменений |
| `dist_deadband_near` | `0.12` | `0.12` | без изменений |
| `dist_deadband_far` | `0.05` | `0.05` | без изменений |
| `stop_range` | `0.30` | `0.30` | без изменений |

Числа в [`stage1.launch.py`](../../src/mentorpi_bringup/launch/stage1.launch.py) и в As-built
[tech.md](tech.md) совпадают с этой таблицей.

Ниже — исходный протокол четырёх прогонов (не выполнялся).

## Безопасность

Охраны столкновений (**F12**, **F13**) **нет** — робот **не тормозит** перед предметами и
видит только человека-цель. Все прогоны — на **ровном полу**, в **свободном секторе** впереди
и сзади (достаточно места для подъезда, отъезда и ручного свипа).

Оператор **у пульта** на всём протоколе. Мгновенный стоп:

- кнопка **Select** на пульте → режим **Manual**, канал следования отключается, стик даёт нули
  вместо `/pnc/desired_twist`;
- на хосте Pi под рукой: `t1ctl mode forbid`.

Робота в движение приводит **только оператор** (стик в **Manual** или следование в
**AutoFollow** с живым человеком-целью). Запрещены ненулевые Twist от агента, `ros2 topic pub`
в `/cmd_vel`, `/vehicle/cmd_vel`, `/hiwonder_controller/cmd_vel` и любые иные команды движения
не от оператора.

Источник — as-built [tech.md](tech.md) `### As-built`, [SD012](../SD012/tech.md),
[SD020](../SD020/measure.md), [SD022](../SD022/measure.md), [SD004](../SD004/tech.md). Новых
допусков здесь нет.

| Величина | Значение | Откуда |
|----------|----------|--------|
| путевая `max_linear` | `0.37` м/с | SD020, Замер 1 |
| `max_angular` | `2.0` рад/с | SD020 |
| `track_half_sum` | `0.1407` м | SD020 |
| пультовая анти-мёртвая зона по линейной | `linear_min = 0.10` м/с | SD004, `stage1.launch.py` |

| глубина `/aurora/points2` на стенде | **2.15 Гц** (период ≈465 мс) | SD022, штатная батарея |
| рабочий диапазон глубины Aurora | **0.3–3 м** | SD012 |

Параметры, **не** входящие в этот замер, но нужные на стенде (unchanged I3):

| Параметр | Значение в launch | Комментарий |
|----------|-------------------|-------------|
| `standoff` | `0.5` м | целевая дистанция, без изменений в SD024 |
| `max_linear` | `0.37` м/с | путевой потолок платформы, не трогаем |
| `nearest_timeout_ms` | `300` | окно свежести сообщения (D4) |
| `points_timeout_ms` | `700` | допуск возраста облака (D5) |

**Ограничение ноды (D3):** `stop_range < standoff − dist_deadband_near` и
`max_linear_follow ≤ max_linear`. Нарушение — падение на старте; подбирать `stop_range` с
учётом уже выбранного `dist_deadband_near`.

**Одометрия.** В SD020 зафиксировано: `/odom_raw` слепа к физическому уводу по курсу и не
годится как единственный свидетель «поехал / не поехал» без оговорки. Для свипа страгивания
(прогон 1) свидетель — `/imu_odom` в скрипте `/tmp/sd024_measure_breakaway.py`. Для прогонов
2–4 контур замкнут на `/perception/nearest_person`, не на odom.

## Прогон 1 — свип страгивающей линейной (`min_breakaway_linear`)

**Постановка.** Робот на полу с чистым сектором вокруг, штатная батарея (глубина **2.15 Гц**,
как в прогонах SD022). Режим **Manual** (не **Forbidden**, не **AutoFollow**). Оператор ведёт стик строго по **линейной** оси
(`linear_axis: 1` — вперёд/назад; боковая ось разворота не используется). Цель — найти
минимальную **|linear.x|**, при которой гусеницы **катятся**, а не только гудят / ползут с
проскальзыванием.

Если анти-мёртвая зона пульта блокирует свип ниже `linear_min = 0.10` м/с (наследие SD004 в
`stage1.launch.py`), на время этого прогона оператор **временно** понижает `linear_min` в launch
(как в SD022 T8 временно опускали `angular_min`), проводит свип и **возвращает** `linear_min`
к `0.10`. Конкретное временное значение в протокол не подставляем — выбирает оператор по
ходу свипа. Скрипт сам напишет, если все команды упёрлись в `0.10`.

Свидетель: джойстик (ось 1) как референс усилия, `/hiwonder_controller/cmd_vel` — команда
на моторы, `/imu` — факт старта. Таблицу оператор не заполняет.

**Что снимать.** Скрипт `/tmp/sd024_measure_breakaway.py` (только подписки). 3 с постоять,
стик в нуле. Дальше свободно качать стик вперёд/назад и отпускать; скрипт сам отмечает
страгивания. Ctrl+C — min/max усилия.

На хосте Pi скопировать скрипт в контейнер и запустить:

```bash
docker exec -it -u ubuntu mentorpi-t1 bash -lc 'source /home/ubuntu/ros2_ws/.hiwonderrc; export ROS_LOCALHOST_ONLY=0; source /home/ubuntu/mentorpi_t1_ws/install/setup.bash; PYTHONUNBUFFERED=1 python3 /tmp/sd024_measure_breakaway.py'
```

`.hiwonderrc` включает `ROS_LOCALHOST_ONLY=1`; launch overlay его сбрасывает. Без `export ROS_LOCALHOST_ONLY=0` скрипт не видит `/joy`, `/imu` и cmd_vel, хотя робот едет.

**Куда записать.** Вставить таблицу и строки min/max из вывода скрипта:


## Прогон 2 — коридор (`dist_deadband_near`, `dist_deadband_far`)

**Постановка.** Режим **AutoFollow**. Человек-цель стоит на дистанции около `standoff`
(`0.5` м в launch) — лицом к роботу, устойчиво в кадре и детекции. Оператор **медленно**
смещает себя вперёд/назад через границу коридора, не делая резких рывков. Глубина камеры на
стенде — **2.15 Гц** (наследие SD022); именно при этом периоде облака проверяем, не «дышит»
ли робот на границе (чередование подъезда и отъезда при почти постоянной дистанции).

Подбор: оператор меняет `dist_deadband_near` и/или `dist_deadband_far` (через правку launch
или `ros2 run … --ros-args -p …` и перезапуск `motion_control`), повторяет постановку, пока на
границе коридора вердикт не станет **«стоит»**, а не **«дышит»**. Числа кандидатов в протокол
не подставляем — только снятые оператором.

Мгновенный стоп: **Manual** (Select) или **Forbidden** (`t1ctl mode forbid`).

**Что снимать.** Три терминала параллельно во время движения у границы:

```bash
ros2 topic echo /perception/nearest_person
```

```bash
ros2 topic echo /pnc/desired_twist
```

```bash
ros2 topic echo /vehicle/cmd_vel
```

Смотреть: `person.x`, `person.y` (или эквивалент в msg), `valid`, `coasting`, вычисленный
`range ≈ hypot(x, y)`; `linear.x` / `angular.z` в desired и vehicle (ожидается `angular.z = 0`
— угловой канал временно выключен SD024).

**Куда записать.**

| Попытка | `dist_deadband_near` | `dist_deadband_far` | Вердикт (дышит / стоит) | Заметка (range, desired linear.x) |

| 1 | ____ | ____ | ____ | ____ |
| 2 | ____ | ____ | ____ | ____ |
| 3 | ____ | ____ | ____ | ____ |

## Прогон 3 — стоп-порог (`stop_range`)

**Постановка.** Режим **AutoFollow**. Человек-цель **подходит** к роботу вплотную, пока
перцепшн не перестанет отдавать валидную цель или оператор не зафиксирует дистанцию, ниже
которой следование должно жёстко обнуляться (`stop_range`). Рабочая глубина Aurora на стенде —
**0.3–3 м** (SD012); ближе нижней границы камера человека не измеряет, `valid` гаснет сам.

Выбранный `stop_range` должен удовлетворять **D3:** `stop_range < standoff − dist_deadband_near`
(использовать **снятые** в прогоне 2 `dist_deadband_near`, не стартовое `0.12` из I3). Не
ставить `stop_range` ниже смысла «жёсткий стоп внутри коридора отъезда» — см. негативный
сценарий №1 в [solution.md](solution.md).

Мгновенный стоп: **Manual** (Select) или **Forbidden** (`t1ctl mode forbid`).

**Что снимать.**

```bash
ros2 topic echo /perception/nearest_person
```

При необходимости — рулетка от носа робота до оператора на ключевых точках (запись в
«Физически» ниже).

Фиксировать по мере сближения: `valid`, `coasting`, `range` (и `x`, `y`), момент, когда
`valid` стал `false` или `coasting` повлиял на гейт.

## Прогон 4 — потолок скорости следования (`max_linear_follow`)

**Постановка.** Режим **AutoFollow**. Человек-цель отходит от робота **дальше коридора**, чтобы
сработал подъезд. Оператор оценивает, какая максимальная скорость подъезда **безопасна** на
этой площадке (зазор до стен/мебели, комфорт торможения, отсутствие F12/F13). Параметр
`max_linear_follow` **не может превышать** путевой `max_linear = 0.37` м/с (SD020) — нода
проверяет это на старте (D3).

Подбор: оператор задаёт кандидата `max_linear_follow` в launch, перезапускает ноду, повторяет
отход/подъезд, фиксирует вердикт (**слишком быстро / норм / медленно**) и пики в топиках.
Конкретные кандидаты в протокол не подставляем.

Мгновенный стоп: **Manual** (Select) или **Forbidden** (`t1ctl mode forbid`).

**Что снимать.**

```bash
ros2 topic echo /pnc/desired_twist --field linear.x
```

```bash
ros2 topic echo /vehicle/cmd_vel --field linear.x
```

На установившемся подъезде — пик и удерживаемая `linear.x` в обоих топиках; вердикт оператора.

**Куда записать.**

| Попытка | `max_linear_follow` (в launch) | Пик `desired linear.x` | Пик `vehicle linear.x` | Вердикт оператора |
|---------|--------------------------------|------------------------|------------------------|-------------------|
| 1 | ____ | ____ | ____ | ____ |
| 2 | ____ | ____ | ____ | ____ |
| 3 | ____ | ____ | ____ | ____ |
