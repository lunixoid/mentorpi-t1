# Замер скоростей для следования (F11)

Операторский документ. Цель — заменить прикидочные параметры `solution.md` (дистанция удержания, `max_linear`, `max_angular`, предельная скорость ухода человека) измеренными на железе значениями. В `t1ctl` не входит: это ручные замеры на стенде.

**Безопасность.** Охраны столкновений (F12/F13) ещё нет — во время замеров робот **не тормозит перед предметами**. Все замеры — в свободном пространстве, робот на ровном полу, рядом дежурит оператор с `t1ctl mode forbid` наготове (мгновенный стоп).

Что известно из кода (не замер, а геометрия `tank_kinematics.py`):

- диаметр колеса `0.075` м → окружность `π·0.075 = 0.2356` м;
- перевод скорости в обороты трека: `об/с = скорость / 0.2356`;
- колёсная база `0.1368` м, колея `0.1446` м; при довороте track-скорость внешнего трека = `linear_x + angular_z·(0.1368+0.1446)/2 = linear_x + 0.1407·angular_z`.
- Реальный **максимум оборотов мотора зашит в прошивку STM32** (в репозитории её нет) — поэтому потолок скорости из кода не выводится, только замеряется (Замер 1).

## Замер 1 — envelope робота (с джойстика)

Цель — подтвердить, что рабочий envelope следования (`max_linear`, `max_angular`, тот же, что у ручного режима) **реально достигается контуром чисто**, и снять достигнутые значения из `/odom_raw`.

Измерять только через джойстик.

Подготовка: робот на свободном полу (≥3 м прямого хода), `t1ctl mode manual`, полное отклонение стика соответствует `max_linear` / `max_angular` из параметров `pad_teleop` (по умолчанию 0.5 / 2.0).

### Линейная (`max_linear`)

Стик **строго вперёд до упора**, робот едет прямо; в отдельном терминале — достигнутая скорость:

```
ros2 topic echo /odom_raw --field twist.twist.linear.x
```

Взять установившееся значение (после разгона, на прямом участке). Это `max_linear` — реально достигаемая линейная скорость нашего envelope.

| Проход | Команда (полный стик), м/с | Достигнуто (odom), м/с | \|перемещение\| odom, м | Физически (рулетка), м |
|--------|----------------------------|------------------------|------------------------|------------------------|
| 1 (odom_max_liner_run1) | 0.5 | 0.44 устойч. / 0.5 пик | 1.35 | 1.0 |
| 2 (odom_max_liner_run2) | 0.5 | 0.38 устойч. / 0.5 пик | 1.42 | 1.0 |

Кросс-проверка одометрии (в `calibrate_params.yaml` поправка `linear 0.96`): разметить метку, проехать полным стиком, засечь секундомером. `скорость = путь / t`.

**Результат: путевая max_linear = 1.0 м / 2.67 с = 0.375 м/с** при полном стике (команда 0.5).

Сверка с odom по скорости:
- run2 odom cruise 0.376 м/с ≈ секундомерные 0.375 — совпадает;
- run1 odom cruise 0.44 м/с — выше на ~17 % (разброс проскальзывания между прогонами).

То есть по **скорости** одометрия примерно верна (0–17 %), а `|перемещение|` odom 1.35–1.42 м — это **вся записанная прокрутка** (робот катился и вне размеченного метра), не масштабная ошибка. **В конфиг F11 идёт путевая `max_linear ≈ 0.37 м/с`.** Одометрию F11 всё равно не использует (см. «Наблюдение Замера 1»).

### Угловая (`max_angular`)

Стик **строго вбок до упора**, робот крутится на месте:

```
ros2 topic echo /odom_raw --field twist.twist.angular.z
```

| Проход | Команда (полный стик), рад/с | Достигнуто (пик odom), рад/с | Перемещение x,y odom, м |
|--------|------------------------------|------------------------------|-------------------------|
| 1 (odom_max_angular_run1) | 2.0 | 2.0 | (0, 0) — на месте |
| 2 (odom_max_angular_run2) | 2.0 | 2.0 | (0, 0) — на месте |

Пик угловой = `max_angular` = **2.0 рад/с** достигнут; перемещение (x,y) = 0 → робот крутится на месте чисто (в каждом прогоне крутили в обе стороны, поэтому средняя ≈ 0, значим именно пик).

> Если понадобится проверить, тянет ли платформа **выше** ручного envelope (0.5 / 2.0) — это отдельная процедура: остановить `stub_graph`, перейти в `AutoFollow` и стать **единственным** публикатором `/pnc/desired_twist` (`ros2 topic pub`), тогда конфликта нет. В рамках F11 это не нужно: следование сознательно не превышает ручной предел (`solution.md`).

### Наблюдение Замера 1 — увод по курсу, одометрия слепа (важно для F11)

При чистой команде «вперёд» (`angular.z = 0`) робот физически уводит по курсу на **20–30° за метр** (кренит влево, ближе к концу уходит вправо). Разбор бэгов `odom_max_liner_run1/2`:

- `angular.z` в odom **≡ 0.0000** рад/с на всём проходе, интеграл рыскания `Δyaw = 0.0°`, траектория odom прямая (`путь = хорда`).
- То есть **одометрия не видит физический увод**: энкодеры считают треки равными, а по полу робот кривит. Причина — проскальзывание / асимметрия тяги траков, не команда.

**Следствие для F11 (определяет закон управления):**

1. Контур F11 **нельзя замыкать на `/odom_raw` по курсу** — одометрия слепа к физическому уводу (`angular.z≡0` при реальном крене). Ехать «прямо по одометрии» = уехать вбок на 20–30°/м. (По скорости odom ≈ верна, но дистанцию до человека одометрия в принципе не даёт — только собственный пробег.)
2. Сервить только на цель из `/perception/nearest_person`: `range` → дистанция удержания, пеленг `atan2(y, x)` → доворот. Внешняя референция (человек) — единственный источник, который видит реальный увод.
3. Увод (~8–12°/с при 0.3–0.4 м/с) парируется тем же угловым каналом, что и центрирование; запас до `max_angular` (2.0 рад/с ≈ 115°/с) — с избытком. Это же усиливает риск перерегулирования: угловой канал нагружен и центрированием, и парированием увода — коэффициенты подбираются в Замере 3.
4. Вне F11 (железо/калибровка): проверить натяжение траков и калибровку одометрии; продуктовое углубление одометрии — F15. F11 на это не закладывается.

### Насыщение поворота-в-движении

Из замеренного `max_linear` посчитать, при какой угловой скорости внешний трек упирается в тот же потолок на ходу:

```
внешний трек = linear_x + 0.1407 · angular_z
angular_запас = (max_linear − linear_x) / 0.1407
```

Пример: если `max_linear ≈ 0.5` и робот едет `0.4` м/с, то на доворот остаётся `(0.5−0.4)/0.1407 ≈ 0.7` рад/с прежде чем внешний трек насытится и поворот исказится. Это ограничение сверху на угловую при движении — учитывается в законе управления F11 (Замер 3).

## Замер 2 — скорость ухода человека

Не нужен внешний измеритель: скорость берём из того же сигнала, что читает F11 — `/perception/nearest_person` (`range`, `x`, `y` в базе робота).

Робот стоит (`t1ctl mode forbid`), человек уходит от него по прямой спокойным, затем быстрым шагом.

```
ros2 bag record -o egress /perception/nearest_person
# человек уходит ~5 м спокойным шагом, затем повтор — быстрым
```

Обработка: `range(t)` продифференцировать (`Δrange/Δt` на прямом участке) → скорость ухода, которую **видит сенсор**. Записать спокойный и быстрый шаг.

| Проход | Скорость ухода (по range), м/с | Разброс x/y (шум пеленга), м |
|--------|-------------------------------|------------------------------|
| спокойный шаг | ____ | ____ |
| быстрый шаг | ____ | ____ |

`max_target_speed` для конфига — берём **спокойный шаг** (гарантируемый режим), и он должен быть **ниже замеренного `max_linear`** с запасом на доворот. Разброс `x/y` — оценка шума пеленга: именно он, а не скорость, задаёт, насколько агрессивно можно крутить без рывков.

## Замер 3 — перерегулирование (приёмка F11, после реализации)

Замкнутый контур: цель идёт «змейкой», смотрим, не рвёт ли робот по курсу.

```
ros2 bag record -o overshoot /perception/nearest_person /pnc/desired_twist /odom_raw
# человек идёт змейкой перед роботом в AutoFollow
```

Обработка: наложить пеленг цели `atan2(y, x)` на `angular.z`. Перерегулирование = угловая команда **осциллирует / проскакивает** ноль пеленга. Критерий приёмки: за `max_target_speed` угловая команда сходится к пеленгу без затухающих колебаний; при превышении скорости ухода — плавная деградация, без разворотов на `max_angular`.

Здесь же подбирается `standoff` (по умолчанию 0.5 м): робот встаёт перед человеком, при сближении ближе не пятится, при удалении снова подъезжает.
