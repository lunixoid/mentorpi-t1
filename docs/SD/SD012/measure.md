# Замер крепления лидара и камеры

Операторский документ. В вывод `t1ctl` не входит. Числа вводятся командами `t1ctl calib lidar` и `t1ctl calib camera` как есть: **метры** для высоты, **градусы** для наклона, без суффиксов (`0.168`, не `168`, не `0.168m`).

Робот стоит на **ровном полу**, неподвижен. Высота — всегда **вертикаль от пола** (плоскость гусениц), не вдоль оптической оси и не от крышки корпуса.

То, что печатает `t1ctl calib` третьим числом в `lidar xyz` / `camera xyz`, — та же высота от пола. После ввода источник этих величин станет `measured`.

Схемы: [Схема — замер лидара](design/Схема%20—%20замер%20лидара.html), [Схема — замер камеры](design/Схема%20—%20замер%20камеры.html).

## Стенд `pi@192.168.2.2` (27.08.2026)

Замер по этой методике, не заводские origin из xacro.

| Сенсор | Точка | Высота от пола | Наклон |
|--------|--------|----------------|--------|
| лидар LD19 | середина оптического кольца | 0.180 м (18 см) | плоскость параллельна полу: pitch 0°, roll 0° |
| камера Aurora 930 | середина корпуса / окна глубины | 0.145 м (14.5 см) | сюда не входит (`corner`) |

```
t1ctl calib lidar --height 0.18 --pitch 0 --roll 0
t1ctl calib camera --height 0.145
```

В `t1ctl calib` без файла заводские высоты другие: лидар ≈ 0.168 м, камера ≈ 0.177 м. Разница после ввода ожидаема.

## Лидар (LD19)

Нужны три числа: высота, pitch, roll. Разворот вокруг вертикали (`yaw`) сюда не входит — его считает этап `drive`.

### Высота `--height`

Точка **L** — середина оптического окна (тёмное кольцо / щель по окружности корпуса). Это плоскость скана. Не верхняя крышка, не кронштейн, не кабель, не край кожуха.

От пола рулеткой **вертикально** до **L**. Записать в метрах. На стенде T1: `0.18`.

```
        бок робота, нос вправо

                    .----.  крышка — не мерить
                   (  L  )  ← середина окна = плоскость скана
                    '----'
                      |
                      |  H  (--height)
                      |
        ==============+==============  пол (гусеницы)
```

### Наклон `--pitch` и `--roll`

Знак — как в ROS: ось x вперёд, y влево, z вверх.

- **pitch** — наклон вокруг поперечной оси. Перед скана выше зада — число **положительное**.
- **roll** — наклон вокруг продольной оси. Правый борт ниже левого — число **положительное**.

Робот на ровном полу. Инклинометр или уровень в телефоне положить на **верх крышки** лидара (у LD19 крышка параллельна плоскости скана):

- для pitch — вдоль носа робота;
- для roll — поперёк, левый–правый борт.

Нет инклинометра: два замера высоты точки L, затем угол.

- pitch: высота L у переднего края корпуса и у заднего, база — расстояние между точками вдоль носа.
  `pitch_deg = atan2(H_перед − H_зад, база) × 180 / π`
- roll: высота L у правого и левого края, база — между ними поперёк.
  `roll_deg = atan2(H_лев − H_прав, база) × 180 / π`

Горизонтальный скан — `0` и `0`.

### Ввод

```
t1ctl calib lidar --height 0.18 --pitch 0 --roll 0
```

Нужны все три опции. Затем `t1ctl calib accept`.

## Камера (Deptrum Aurora 930)

Нужна только высота. Наклон камеры считает этап `corner`. Эту команду используют, когда полоса пола не попала в кадр (камера задрана вверх) и `calib corner` сказал ввести высоту вручную.

### Высота `--height`

Точка **C** — центр переднего окна модуля глубины (IR / depth), не RGB-линза, не верх корпуса, не кронштейн, не кабель.

От пола рулеткой **вертикально** до **C**, даже если камера смотрит вверх. Не вдоль оптической оси.

```
        бок робота, нос вправо

                     /|  окно глубины, центр = C
                    / |
                   /  +  ← C
                  /   |
                      |
                      |  H  (--height)
                      |
        ==============+==============  пол (гусеницы)
```

Заводская высота в модели около `0.177` м; на стенде замерено `0.145`. Записать в метрах.

### Ввод

```
t1ctl calib camera --height 0.145
```

Затем `t1ctl calib accept`. Остальные величины камеры команда не трогает.

## После замера

`t1ctl calib save` и `t1ctl restart`. В `t1ctl calib` введённые оси должны быть `measured`, вычисленные этапы — `computed`.
