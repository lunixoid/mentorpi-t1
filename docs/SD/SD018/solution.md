# SD018. Pre-commit: clang-format и проверки Python

## Проблема
1. В репозитории нет общего стиля C++ и Python и нет шлюза перед коммитом. Формат разъезжается между ROS-нодами, `t1ctl` и launch-файлами; агент и разработчик правят код разными встроенными линтерами.
2. Обход — смотреть стиль глазами на ревью или не смотреть вовсе. На Pi и в CI проверки формата нет; откатывать чужой reformat вместе с логикой неудобно.

## Решение
Перед каждым коммитом локальный Git-хук сам приводит C++ и Python к фиксированному стилю и не даёт закоммитить код, который хук не принял. Существующее дерево один раз приводится к этому стилю. Сборку робота и CI это не затрагивает.

## Сценарии

### Позитивный
1. Разработчик (или агент) меняет C++ или Python в overlay и хочет сохранить коммит в git.
2. В корне репозитория установлен хук `pre-commit`
   1. При `git commit` хук форматирует стейджед C++ и Python и проверяет Python линтером
3. Все хуки проходят
   1. Коммит создаётся; стиль файлов совпадает с каноном репозитория

### Негативный №1
1. Пункты позитивного сценария №1–2
2. Линтер Python находит нарушение или хук переписал файлы
   1. Коммит не создаётся; нужно поправить или добавить переписанные файлы в индекс и повторить `git commit`

### Негативный №2
1. Пункты позитивного сценария №1
2. Хук в `.git/hooks` не установлен (`pre-commit install` не выполняли)
   1. `git commit` проходит без проверки стиля; полный прогон остаётся ручной командой `pre-commit run --all-files`

## Функциональные требования
- Должна быть возможность поставить локальный хук, который срабатывает на `git commit` в корне репозитория
- Хук должен форматировать C++ по clang-format и проверять Python (формат и линт)
- Хук должен блокировать коммит, если проверка не прошла или файлы были переписаны
- Должна быть возможность прогнать те же проверки по всему дереву одной командой
- Существующий C++ и Python репозитория должны быть приведены к этому стилю в рамках того же изменения

## Нефункциональные требования
- Проверки только локальные: CI (GitHub Actions и аналоги) в это изменение не входят
- Стиль C++ — Google, 100 колонок; Python — black / isort / flake8 с длиной строки 120, как в эталоне kanban-analyzer
- yamllint, vulture, clang-tidy, сборка overlay и деплой на Pi в это изменение не входят
- Версии ROS-пакетов не поднимаются: меняется процесс разработки, не поведение робота
