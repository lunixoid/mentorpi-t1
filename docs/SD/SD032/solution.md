# SD032. rviz2 на рабочем столе VNC

## Проблема
1. Оператор заходит на робот по VNC и хочет смотреть 3D-сцену demo-контура в rviz2 с рабочего стола. Внутри контейнера `mentorpi-t1` команда `rviz2` не открывает окно: нет дисплея для графики, ярлыка на столе нет.
2. Обход: Foxglove Desktop на Mac. Мост Foxglove поднимается вместе со стеком и в статусе предлагается как основной просмотр.

## Решение
На рабочем столе VNC в demo появляется ярлык: по нему вручную открывается rviz2 с готовой 3D-сценой платформы. Вместе с контуром графические окна сами не стартуют и не мешают роботу работать. Foxglove остаётся запасным просмотром с Mac: по умолчанию выключен и не предлагается, включить его можно командой `t1ctl debug on`. Stock не меняется.

## Сценарии

### Позитивный
1. Demo-контур поднят. Оператор хочет видеть 3D-сцену робота с рабочего стола VNC, без Foxglove на Mac.
2. Оператор подключается по VNC
   1. На рабочем столе есть ярлык запуска rviz2
3. Оператор открывает ярлык
   1. Открывается rviz2 с 3D-сценой: модель платформы, TF, лидар, облако точек камеры
4. Если оператору нужен запасной просмотр с Mac
   1. Включает `t1ctl debug on`
   2. Мост Foxglove поднимается, дальше можно смотреть как в SD005

### Негативный №1
1. Пункты позитивного сценария №1–3, но дисплея нет или графика в контейнер не проброшена
   1. rviz2 не открывает окно
   2. Demo-контур продолжает работать, движение и `t1ctl` не блокируются

### Негативный №2
1. Demo не активен (контур не поднят или включён stock)
   1. Ярлык не открывает 3D-сцену demo. Stock и хост не ломаются

### Негативный №3
1. Пункты позитивного сценария №1–3, `t1ctl debug` выключен
   1. Мост Foxglove не запущен и не предлагается как основной просмотр
   2. Ярлык rviz2 на VNC при этом работает

## Функциональные требования
- Должна быть возможность открыть rviz2 с рабочего стола VNC ярлыком, без ручного набора команды в терминале
- Ярлык должен открывать rviz2 с готовой 3D-сценой demo: фиксированный кадр `odom`, модель `/robot_description`, дерево TF платформы и сенсоров, лидар `/scan`, облако точек `/aurora/points2`
- rviz2 не должен стартовать сам вместе с demo: только по ярлыку
- Графические приложения не должны блокировать работу demo-контура, в том числе если окно не открылось или позже графику запустят
- Мост Foxglove не должен стартовать вместе с demo по умолчанию
- Пока `t1ctl debug` выключен, Foxglove не должен предлагаться оператору как основной просмотр
- Должна быть возможность включить запасной мост Foxglove командой `t1ctl debug on` (это же имя команды, что overlay людей в SD014)
- Изменение действует только в demo (`mentorpi-t1`). Stock (`MentorPi`) не меняется

## Нефункциональные требования
- Вход на рабочий стол — уже доступный VNC вендорского образа; новый VNC-сервер в этом SD не заводим
- Графика контейнера — проброс дисплея хоста в `mentorpi-t1`, без отдельного GUI-стека на каждое окно
- Просмотр в rviz2 — для отладки, read-only: управление движением из rviz2 не входит
- Запасной путь Foxglove на Mac по составу сцены не расширяем: как в SD005
- Не входят: автозапуск rviz2 со стеком, ярлык и rviz2 в stock, новый операторский экран вместо рабочего стола VNC, 2D-панели изображения и графиков IMU в ярлыке (это запасной Foxglove)
- Цифры задержки открытия окна и нагрузки CPU от rviz2 не заданы
