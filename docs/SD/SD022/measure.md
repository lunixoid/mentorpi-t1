# Замер поперечного знака (лево/право) — диагноз слоя

Операторский документ T6 [SD022](tech.md). Цель — **назвать слой** сверкой одного предмета в трёх
потоках (`/scan`, `/aurora/points2`, `/aurora/rgb/image_raw`). Эталон стороны — лидар (REP-103:
влево от носа → `y > 0` → пеленг положительный). Правка кода и сохранение калибровки в этот
прогон **не входят**.

В `t1ctl` не входит: это постановка сцены и журнал снятого. Числа пеленгов и вердикт слоя
сюда **переписываются с вывода команды после прогона**, не из этого абзаца и не из примера
контракта I1 в `tech.md`.

**Безопасность.** Охраны столкновений (F12/F13) нет. Робот стоит. Пульт не трогать. Рядом —
`t1ctl mode forbid` (мгновенный стоп). Никаких ненулевых Twist, `ros2 topic pub` в cmd_vel и
`AutoFollow` в этом замере нет: этап `side` на шасси не публикует.

**Не сохраняем калибровку.** Запрещены `t1ctl calib accept` и `t1ctl calib save`. После
успешного прогона этап кладёт предложение в **черновик** (это не действующий файл). Черновик
сбросить: `t1ctl calib reject`. `abort` — только если нужно вычистить весь черновик; принятые
раньше этапы он тоже снимет с черновика, основной yaml не трогает.

## Границы железа (уже сняты, не SLA этого замера)

Источник — as-built [SD012](../SD012/tech.md) / [SD012/measure.md](../SD012/measure.md) и
переприёмка [SD021](../SD021/tech.md) T3. Новых допусков здесь нет.

| Величина | Значение | Откуда |
|----------|----------|--------|
| плоскость скана LD19 | 0.180 м от пола, pitch 0°, roll 0° | SD012, 27.08.2026 |
| высота Aurora 930 | 0.145 м от пола (середина корпуса / окна глубины) | SD012 |
| FOV камеры | 74° × 51° | SD012, datasheet Aurora 930 |
| глубина (спека) | 0.3–3 м (нижняя граница вендора ещё 0.15 м) | SD012 |
| глубина, что уже видели на стенде | 0.36–2.36 м (`range` nearest в бэге F11 после SD021 T2) | SD021 T3 |
| облако | организованное 640×400, `/aurora/points2` | SD012 / SD008 |
| кадр | `/aurora/rgb/image_raw` | SD008 |

Рабочее окно этапа `side` (константы кода, не критерий точности): фронтальный сектор **±40°**,
дальность **0.30–3.0 м**. Предмет вне этого окна этап не ищет.

Коробка должна **пересекать плоскость скана** (0.180 м): высота 0.3–0.5 м от пола. Ниже скана
лидар её не увидит.

Полуширина камеры ≈ 37°. Пеленг 20–25° в кадре есть; 40° уже у края поиска этапа.

## Реквизит

- матовая светлая коробка высотой **0.3–0.5 м** (не зеркальная, не чёрная матовая «дыра»
  глубины);
- рулетка;
- (по желанию) вторая коробка **другого** размера/цвета — асимметрия в одном кадре.

Робот на **ровном полу**, неподвижен, нос в свободное пространство. Прямой угол комнаты для
этого замера **не нужен** (угловая сцена зеркало не показывает, D1.1).

Детектор людей на Mac **не нужен** и в сверку не входит: измерение выше детекций, по сырым
потокам.

## Постановка

Одна коробка явно с **одной** стороны. Пеленг от оси носа 20–25°, дистанция 1.0–1.5 м.

```
        вид сверху, нос вверх

                    20–25°
                      /
                     /   [коробка]     ← 0.3–0.5 м высотой
                    /    1.0–1.5 м от робота
                   /
        ----------+----------  ±40° чистый сектор
                  ^
               робот
```

Знак: **слева** от носа — `--side left` (пеленг плюс); **справа** — `--side right` (пеленг
минус). `--side` обязан совпасть с тем, куда поставили коробку глазами. Иначе этап откажет
`lidar side disagrees with operator` — это не слой (a)/(b).

Поперечное смещение (чтобы не целиться «на глаз» в угол):

| Дистанция | 20° вбок | 25° вбок |
|-----------|----------|----------|
| 1.0 м | 0.34 м | 0.42 м |
| 1.2 м | 0.41 м | 0.51 м |
| 1.5 м | 0.51 м | 0.63 м |

`поперек = дистанция · sin(пеленг)`. Мерить от продольной оси робота, не от края гусеницы.

### Чистота сцены

- в секторе **±40°** от носа — нет других компактных предметов (стулья, ноги, второй робот);
- от коробки **≥ 0.5 м** до любого постороннего предмета;
- стены и мебель — дальше коробки и шире, чем компактный кластер (иначе этап может взять не
  её);
- пол без блестящих луж под камерой.

### Две коробки (необязательно)

Разные коробки слева и справа, чтобы в одном RGB-кадре было видно, какая сторона «чья».
Этап берёт **ближайший** компактный кластер. Измеряемая коробка должна быть ближе второй
(зазор по дальности заметный, не два предмета на одном радиусе). `--side` — сторона
**ближайшей**. Метка на PNG рисуется по кластеру облака этой ближайшей.

## Предусловия на Pi

Стенд `pi@192.168.2.2` (Wi-Fi `192.168.149.1`). `t1ctl` — в PATH **хоста Pi**, не в контейнере.
Нужен `t1ctl` **1.6.0** (команда `calib side`, копирование кадра в `/tmp/t1ctl-side_frame.png`).
Если версии нет — сначала выкладка T5 оператором, этот протокол сам код не выкладывает.

Контур `mentorpi-t1` поднят, лидар и камера **оба** `active`. Режим — `forbidden` (робот
стоит). Действующий `sensor_calibration.yaml` **не менять** (ось X SD021: `depth_cam.rpy`
`(0,0,0)`, высота камеры 0.145 м, лидар 0.180 м).

## Прогон

Все команды — на хосте Pi, если не сказано иное. Робота в движение не переводить.

### 1. Сессия и контур

```bash
ssh pi@192.168.2.2
# или: ssh pi@192.168.149.1
```

```bash
t1ctl --version
```

Ожидается:

```
1.6.0
```

```bash
t1ctl start
```

Если контур уже жив — `Started.` или сообщение, что уже запущен. Затем:

```bash
t1ctl mode forbid
t1ctl status
```

Ожидаемый вид (числа версий/degraded модели могут отличаться; важны demo, mode, lidar,
camera):

```
demo              active
stock             inactive
chassis           active
mode              forbidden
remote controller active
lidar             active
camera            active
imu               active
odometry          active
platform model    degraded
calibration       file
version           1.6.0
```

Если `lidar` или `camera` не `active` — дальше не идти: этап откажет с `no /scan` /
`no camera depth` / `no camera rgb`. Чинить питание/USB, не подставлять вердикт слоя.

### 2. Снимок действующей калибровки (AC3)

До прогона, чтобы после сверить, что основной файл не сдвинулся:

```bash
t1ctl calib
md5sum /home/pi/mentorpi_t1_ws/config/platform/t1/sensor_calibration.yaml
```

Записать вывод `t1ctl calib` (xyz/rpy камеры и лидара) и сумму в поля в конце этого файла.
`depth_cam` rpy после SD021 T2 — нули; если снова виден yaw ≈ 180° — это не этот замер, стоп.

### 3. Поставить коробку

По таблице выше, одна сторона, 1.0–1.5 м, 20–25°. Проверить глазами: коробка в кадре камеры
(не у самого края) и торчит выше кольца лидара. В секторе ±40° больше ничего компактного.

### 4. Снять сторону

Коробка **слева**:

```bash
t1ctl calib side --side left
```

Коробка **справа**:

```bash
t1ctl calib side --side right
```

Окно сбора по умолчанию ~5 с (`--timeout`, как у `corner`). Пока идёт набор — не ходить в
кадр и не двигать коробку.

То же внутри контейнера (не нужно, если `t1ctl` 1.6.0 отработал; тот же префикс, что у
`t1ctl`):

```bash
docker exec -u ubuntu -w /home/ubuntu mentorpi-t1 /bin/bash -c 'export PYTHONUNBUFFERED=1; source /home/ubuntu/ros2_ws/.hiwonderrc >/dev/null 2>/dev/null; export ROS_LOCALHOST_ONLY=0; source /home/ubuntu/mentorpi_t1_ws/install/setup.bash >/dev/null 2>/dev/null; ros2 run mentorpi_calibration calib side --side left'
docker cp mentorpi-t1:/home/ubuntu/mentorpi_t1_ws/config/platform/t1/side_frame.png /tmp/t1ctl-side_frame.png
```

Для правой стороны замените `left` на `right`. Кадр на хосте тогда копируете сами: `t1ctl`
это делает только в основном пути.

### 5. Что смотреть в выводе

Успех (`t1ctl` печатает разобранный контракт, не сырой `T1CTL_CALIB_OK=`). Ниже — **форма**
строк; числа и `layer` подставьте из живого вывода, в документ их заранее не заносить:

```
stage             side
operator          left
scan              <сторона> <пеленг °>
cloud             <сторона> <пеленг °>
layer             <cloud_geometry | pixel_mapping | none>
frame             /tmp/t1ctl-side_frame.png
camera transverse mirror    0 -> <0|1>    computed

  t1ctl calib accept
  t1ctl calib reject
```

Смысл строк:

| Строка | Что это |
|--------|---------|
| `operator` | то, что передали в `--side` |
| `scan` | сторона и пеленг ° по `/scan` в `base_link` |
| `cloud` | то же по `/aurora/points2` |
| `layer` | `cloud_geometry` / `pixel_mapping` / `none` / (отказ) `lidar_suspect` |
| `frame` | кадр **на хосте Pi** после `docker cp` |

Подсказка `accept` / `reject` печатается, потому что этап всегда предлагает поле в черновик.
**В T6 `accept` не нажимать.** Сразу:

```bash
t1ctl calib reject
```

### 6. Куда смотреть кадр

После успеха `t1ctl` копирует PNG из контейнера сюда:

```
/tmp/t1ctl-side_frame.png
```

Проверка, что файл есть:

```bash
ls -l /tmp/t1ctl-side_frame.png
file /tmp/t1ctl-side_frame.png
```

Ожидается `PNG image`, не пустой файл. На Pi GUI может не быть — смотреть на машине
разработки:

```bash
# с Mac, не на роботе:
scp pi@192.168.2.2:/tmp/t1ctl-side_frame.png /tmp/t1ctl-side_frame.png
open /tmp/t1ctl-side_frame.png
```

(Wi-Fi: `pi@192.168.149.1`.)

Метка — жёлтый крест (вертикаль через кадр + короткая горизонталь): колонка, куда перцепшн
проецирует кластер облака. Левая половина картинки = лево робота (камера смотрит вперёд).

Если `frame` = `not found in container` — команда не падает, но смотреть нечего: не
заполнять «куда легла метка», слой (b) по кадру не называть.

Копия рядом с yaml (bind-mount) может лежать ещё в
`/home/pi/mentorpi_t1_ws/config/platform/t1/side_frame.png`. Для журнала T6 канонический путь —
`/tmp/t1ctl-side_frame.png`.

### 7. Как назвать слой (D1.2) — после того как цифры сняты

Не выбирать ветку заранее. По факту прогона:

| Наблюдение | Решение |
|------------|---------|
| скан совпал с `--side`, облако — **противоположная** сторона | **(a)** `cloud_geometry` |
| скан и облако совпали с `--side`, метка на PNG на **противоположной** стороне картинки | **(b)** `pixel_mapping` |
| скан, облако и метка все на той же стороне, что коробка | слой не найден: **стоп-на-уточнение** (даже если F11 по-прежнему зеркалит Y) |
| скан не совпал с `--side` | не (a)/(b): эталон лидара под подозрением, стоп |
| предмет не найден в потоке / молчит сенсор | не вердикт: поправить сцену или контур, повторить |

(a) и (b) взаимоисключающие. Если картина не сводится к перестановке лево/право (ещё и
верх/низ, или «перед/зад») — тоже стоп-на-уточнение, фикс вслепую не начинать.

`layer: none` при метке на верной стороне = стоп-на-уточнение, не «зеркала нет, закрываем
SD». Симптом F11 (человек слева → `person.y < 0`) с переприёмки SD021 никуда не делся.

### 8. Отказы — переставить, не угадывать слой

```
error: calib side failed
detail            no /scan
```

Другие `detail:`: `no camera depth`, `no camera rgb`, `object not found in scan`,
`object not found in cloud`, `lidar side disagrees with operator`, `cannot project to frame`.

Нет предмета в скане — коробка ниже 0.180 м, вне ±40°, слилась со стеной. Нет в облаке —
вне 0.3–3 м, в дыре глубины, слишком тёмная/блестящая. Несколько `detail` сразу — неполный
набор, вердикт по половине данных не пишем.

### 9. Сверка, что yaml не изменился

```bash
t1ctl calib
md5sum /home/pi/mentorpi_t1_ws/config/platform/t1/sensor_calibration.yaml
```

Сумма и позы камеры/лидара — те же, что в шаге 2. Основной yaml не должен получить секцию
`conventions` от этого прогона (`grep conventions` по файлу — пусто, если её не было; либо
то же значение, что до). Черновик после `reject` не держит pending `side`.

**Не делать в этом замере:** `t1ctl calib accept`, `t1ctl calib save`, `t1ctl restart`,
правку overlay / перцепшна / F11, повторный `corner`.

## T8. Минимальная страгивающая угловая (2026-09-05)

Замер для константы `kSd022MinBreakawayAngular` в
[follow_control.hpp](../../../src/motion_control/include/motion_control/follow_control.hpp).

**Постановка.** Робот на полу с чистым сектором вокруг, штатная батарея, `t1ctl mode allow`,
режим `manual`. Оператор ведёт стик по **угловой** оси (`angular_axis: 2`, горизонталь стика;
вперёд/назад — это линейная ось и разворота не даёт). Скрипт-наблюдатель — только подписки,
команд не шлёт — пишет пары: `angular.z` из `/hiwonder_controller/cmd_vel`, то есть то, что
реально дошло до шасси, и `angular_velocity.z` из `/imu`. Одометрия не годится: энкодеры
крутятся и при проскальзывании, гироскоп — честный свидетель. Порог «поехал» — пять сигм шума
гироскопа, но не ниже 0.05 рад/с; шум в трёх прогонах стабилен (sigma 0.0010…0.0013 рад/с).

Пульт на время замера был временно перенастроен: `angular_min 0.40 → 0.02`,
`max_angular 2.0 → 0.6` в [stage1.launch.py](../../../src/mentorpi_bringup/launch/stage1.launch.py).
Первое — чтобы стик вообще мог выдать меньше 0.4, второе — чтобы весь его ход лёг в
измеряемую зону. **После замера параметры возвращены к штатным.**

### Прогон 1 — установившееся вращение по корзинам команды

| `\|cmd\| ω` | N | `\|imu ω\|` ср | вывод |
|---|---|---|---|
| 0.040 | 25 | 0.019 | не движется |
| 0.080 | 53 | 0.010 | не движется |
| 0.100 | 12 | 0.024 | не движется |
| 0.120 | 47 | 0.070 | ползёт, вдвое медленнее команды |
| 0.140 | 39 | 0.105 | ползёт с лагом |
| **0.160** | **220** | **0.158** | **крутится со скоростью команды** |
| 0.180 | 141 | 0.170 | так же |
| 0.600 | 815 | 0.644 | так же |

Корзина 0.060 в сыром выводе помечена «движется» (ср 0.086 при макс 0.726) — это ложное
срабатывание: соседние 0.080 и 0.100 неподвижны, а выброс пришёл с выбега на обратном ходе
стика. Корзины мешают разгон, установившееся вращение и выбег в одну кучу, поэтому был сделан
второй прогон другим методом.

### Прогон 2 — рампы из покоя

Скрипт ловит переход «корпус стоял ≥ 0.5 с → гироскоп вышел из шума» и пишет команду в этот
момент. 13 событий: `0.168, 0.274, 0.301, 0.348, 0.414, 0.427, 0.434, 0.447, 0.467, 0.554,
0.600, 0.600, 0.600`. Медиана 0.434.

**Медиана отброшена.** Три события ровно на `0.600` — это потолок `max_angular` замерочной
конфигурации: команда упёрлась в максимум, а корпус ещё не тронулся. То есть в этих попытках
рука обогнала робота, и записан темп рампы, а не порог гусениц. Разброс 0.168…0.600 — разброс
темпа, не физики; медиана по нему смещена вверх и дала бы 0.43, то есть вернула бы ту самую
резкость, ради устранения которой замер и делался. Показателен здесь **минимум**: 0.168 —
единственная попытка, где рампа была достаточно медленной.

### Результат

Два независимых метода сошлись: установившееся вращение со скоростью команды начинается с
**0.160**, самая медленная рампа из покоя даёт **0.168**. Ниже 0.10 траки не трогаются вовсе,
0.12–0.14 — ползут с проскальзыванием.

Константа в коде — **0.16 рад/с**. Берём порог надёжного страгивания, а не порог «иногда
трогается» (0.12): доворот F11 должен состояться каждый раз. Снимается вместе со всем
временным патчем в SD024.
